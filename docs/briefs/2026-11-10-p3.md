## Scope (Yakov's p3: OVERVIEW's lanes, UI-PLAN.md §4.1)
The patch makes these edits; you only apply it. The pictures and the goldens are not in the patch: you draw them in step 3 from the firmware's own code.
* `parts/oc_ui_overview.h` / `parts/oc_ui_overview.c`: `ui_note_text` (MIDI 36 = `C2`, none = `--`, above 120 clamps to `C9`), `ui_hist_shift` (bit 0 is the newest cell, on the right), `ui_overview_t` / `ui_lane_t`, and `ui_overview_draw`. The header is an inverted 21-column 5x7 bar (`> 120 INT T1 OVERVIEW`, or `  --- EXT T1 OVERVIEW` while the clock follows TR1). Four lanes, 11 pixels each, fill the 47-pixel body: track number, generator, note, `M` or a 5x3 wave for a pending ROLL (the 5x7 face has no `~`), and a 16-cell strip (2-pixel cells, 1-pixel gaps, from x=81). The selected lane is inverted. The footer is 3x5.
* `tests/oc_ui_overview_test.c`: 12 checks (the note names and the shift register), prefix `oc_overview:`. `tools/build_host.sh` runs it before the gfx test.
* `firmware/oc_ui_parts.c`: includes `oc_ui_overview.c`.
* `firmware/oc_port.h`: `oc_gen_label`, `oc_track_last_note`, `oc_track_gate_seen`, `oc_track_muted`, `oc_track_set_mute`, `oc_track_roll_pending`, `oc_track_set_roll`.
* `parts/oc_out.c`: `oc_note_on` stores the last MIDI note and a seen flag (one store each). `oc_track_gate_seen` also ORs the current gate, then clears the flag. `oc_gate_out` wraps the existing write.
* `parts/oc_view.c`: `oc_gen_label` from `oc_tx_desc(TX_MODE)` (ATLAS stays ATLAS). Mute is `P_MUTE` via `oc_track_param_set` (no immediate gate release: that is phase 5). ROLL is `tessera.roll[tr]`.
* `firmware/oc_ui.cpp`: `PAGE_HOME` is four `ROW_TRACK` only; `GEN_NAME[]` is deleted. OVERVIEW is drawn by `ui_overview_draw` in `ui_draw` (the cursor is `oc_selected_track()`). The history is sampled only in `ui_draw`, never in `ui_sample` (the sampler still only queues a ring sample; it shares the tick's interrupt, so nothing slow belongs there). Footer: `L TRK  R OPEN  RL MUTE`. R long (`UI_ACT_CONTEXT`) toggles mute on OVERVIEW. PERFORM uses `oc_gen_label`.
* `tools/render_screens/rs_main.cpp`: after power-on, one control block (`oc_clock_advance(32)`) latches play so the header shows `>`. It then draws `screen-overview-t2.png`, `-mute.png`, `-ext.png` and `-roll.png` (track 2 selected, track 3 muted, following TR1, a ROLL waiting on track 4). A host stub, `rs_clock_ext`, answers `oc_clock_following`.
* `docs/GUIDE.md` and `CHANGELOG.md` (Unreleased, phase 3) describe the lanes. The four new pictures are linked from the GUIDE.
* `docs/STATUS.md`: already done in the ops commit (phase 3 in progress); the row's result at the end (step 6), in its own commit.
* Nothing else: 0 lines in `.github/`, `vendor/`, `docs/briefs/`, `firmware/oc_engine.c`, `firmware/oc_platform.cpp`.
