## What phase 2 is (UI-PLAN §4.4, §5 row 2)

The kit the rest of the UI is built on: a pure-C drawing layer, a new small
face for the footer, one grid every screen obeys, and a snapshot of every
screen a reviewer can read as a diff.

The plan asks for the kit **and** for the grid applied to the phase 1 screens
(the plan's own table: "inverted selection, header/footer grid applied to the
phase 1 screens"). Yakov's answer on 2026-11-08: apply the grid now. The
screens therefore change: an inverted header bar, an inverted cursor row, and
the footer in the 3x5 face.

## The parts

1. **`parts/oc_ui_gfx.h` / `parts/oc_ui_gfx.c`** — the kit. Pure C, no Arduino,
   no engine: it draws into a `uint8_t fb[1024]` the caller passes in, so it is
   host-testable. Primitives: `px`, `hline`, `vline`, `fill_rect`,
   `invert_rect`, a clip rectangle, `text5x7`, `text3x5`, `text5x7_x2` (two
   times the size, for the big numbers of phase 3), `text_right`,
   `ellipsize`. The 5x7 face is Tessera's own (`mono_font.h`, the engine's),
   used as the FM-1's Mono look uses it: a lower-case letter is drawn as its
   capital.
2. **`parts/oc_ui_font3x5.h`** — the new 3x5 face: space, the ten digits, A-Z,
   and `+ - . : / > ~`. Original, drawn for this port, GPL-3.0-only. Four
   pixels a glyph, so 32 columns across the panel.
3. **`firmware/oc_display.cpp`** — the SPI side only, plus `oc_display_fb()`,
   which hands the panel's RAM to the kit. The drawing leaves: the crash
   pager, the safe mode and the splash keep their own thin wrappers, so those
   screens stay **byte-identical** to what `7f5c6b3` drew.
4. **The grid**, in `parts/oc_ui_gfx.h` as constants, applied in
   `firmware/oc_ui.cpp`:

   | Band | Rows | What |
   |---|---|---|
   | header | 0..8 | an inverted bar; the 5x7 title cut out of it at y=1 |
   | body | 9..55 | six text rows, eight pixels a line, the cursor's row inverted |
   | footer | 56..63 | the screen's hints in the 3x5 face at y=58 |

   Six rows is what the phase 1 screens already show, so nothing is lost: the
   body is 47 rows and six rows of an 8-pixel line fill it exactly.
5. **The goldens** — `tests/golden/screen-*.txt`: every screen the renderer
   draws, as 64 lines of 128 `#` (lit) or `.` (dark), so a change to a screen
   is a diff a reviewer can read, where a PNG is a blob. The renderer writes
   them; `tools/build_host.sh` fails if one differs, is missing, or is left
   over. `UI_GOLDEN_UPDATE=1` rewrites them.

## The rules that hold

* Storage stays read only; no engine change; `vendor/tessera` stays at
  `4e4af47`; the engine baseline must pass byte for byte.
* No pin, ISR or SPI change. The kit runs in `loop()`, never in the tick.
* The new names avoid the CI's grep tokens (`format` followed by `(`, and the
  write-path words) — including in comments.
* Every new file: `SPDX-License-Identifier: GPL-3.0-only` and
  `Copyright (C) 2026 Yakov Khalinsky`.
* Never flash, never merge, never force-push. `pio run -e T40` (build only) is
  the one device command.

## What the phase is judged by

* The host tests pass, and `tools/build_host.sh` says the goldens are current.
* `pio run -e T40` builds, and `tools/check_sections.py` says the memory map
  is sound.
* The crash pager and the safe mode are **unchanged**: their goldens are the
  same bytes as on `7f5c6b3`, and the phase 1 screens' goldens are new.
* Yakov's hardware test: flash the hex, and the screen shows the inverted
  header bar, the inverted cursor row, and the footer in the small face.
