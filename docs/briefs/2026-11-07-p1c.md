* Never flash, upload or reflash hardware, and never with a Teensy attached to the build host. Only Yakov flashes, on his own computer. `pio run -e T40` (build only) is the one device command in this job.

* A rejected push means a `STOP:` line with the exact error, and end.

## Scope (docs/UI-PLAN.md, phase 1c: shell wiring, the 1 kHz sampler, the menus, the pages)
The patch makes these edits; you only apply it.
* `firmware/oc_ui.cpp` becomes the UI's shell:
  * the row model stays (`UiRow`, `PAGE_HOME`, `PAGE_PROJ`, `ui_row_text`, `ui_row_turn`); `PAGES[]`, `ui_page`, `ui_row`, `ui_input`, `ui_button` and `ui_page_next` go; `ui_build_rows(screen, tab)` builds a screen's rows (TRACK's from its tab: GEN, SCL, CV, MOD).
  * `encoder_step` applies the 21/22 reverse itself, once.
  * the sampler: `ui_sample` (an `IntervalTimer ui_timer`, 1000 us, `UI_SAMPLE_PRIORITY` 160, below the tick's 80) reads the four buttons (`ui_buttons_now`) and both encoders into `ui_ring` with `ui_ring_put`; `ui_start()` latches the buttons held at boot (`ui_in_init`) and starts it.
  * `ui_service()` drains the ring into the input core (`ui_in_buttons`, `ui_in_turn`), pops the events into the router (`ui_nav_event`) and applies the actions in `ui_apply` (play/stop, restart, the track, the tempo unless following TR1, the value with `ui_accel`, enter, the default on an R long press).
  * the screens in `ui_draw`: OVERVIEW (top line `HOME`), TRACK, PERFORM (stub), PROJECT (load only), INFO (`draw_info`: version, BLK max, draw/flush/loop us, storage, dropped events) and the menu (`draw_menu`); `ui_footer` gives each screen's footer; `ui_open(screen, tab)` is the renderer's way in.
* `firmware/oc_platform.cpp`: `oc_buttons_edges` and the `BUT_*` defines go; `setup()` calls `ui_start()` inside the `!oc_safe_mode` tick block; `loop()` calls `ui_service()` instead of `ui_input()`. The safe mode and the crash pager are unchanged.
* `firmware/oc_diag.cpp`: `oc_diag_blk_max_us()` (read only). `firmware/oc_ui_parts.c` (new): builds `parts/oc_ui_input.c` and `parts/oc_ui_nav.c` into the firmware.
* `parts/oc_ui_nav.c`/`.h`: `ui_nav_open(nav, screen)`; `tests/oc_ui_nav_test.c`: `check_open` (5 checks; oc_nav goes from 42 to 47).
* `tools/render_screens.sh`, `tools/render_screens/Arduino.h` (`micros`, `IntervalTimer`), `tools/render_screens/rs_main.cpp` (`main` renders menu, track, perform, project, info).
* `docs/img/`: `screen-home.png` changes and five PNGs are new. The patch is text only: the pictures are drawn by the firmware's own code, by `tools/render_screens.sh` in step 3, and the check script pins their md5.
* `docs/GUIDE.md` (the controls table, OVERVIEW, the menu, TRACK, PERFORM, PROJECT, INFO; the "Coming" section goes), `README.md` (Layout), `CHANGELOG.md` (one 1c section).
* `docs/STATUS.md`: the 1c row, at the end (step 6), in its own commit.
* Nothing else: 0 lines in `.github/`, `vendor/`, `docs/briefs/`, `docs/UI-PLAN.md`.
